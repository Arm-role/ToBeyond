# Plan: Core loop ใหม่ "เส้นทางคือบิลด์" (ทิศทาง A)

สถานะ: ร่างเพื่อตัดสินใจ ยังไม่เริ่มเขียนโค้ด (2026-11-13)

## 1. เป้าหมาย

- ให้เกมมีเอกลักษณ์ของตัวเอง ไม่ใช่ "Balatro ใส่ธีมทาโรต์"
- บิลด์ต้องเกิดจาก **การออกแบบเส้นทางของโทเคน** ไม่ใช่การสะสม Artifact ที่คูณกันเป็นแถว
- เก็บธีม โลก ภาพ ทิศ ลัทธิ Artifact Chaos Stone ร้านค้า และข้อมูลแบบ `.tres` ไว้ทั้งหมด เปลี่ยนเฉพาะ core loop

## 2. สถานะปัจจุบัน (จากโค้ด)

| ส่วน | ตอนนี้ | ไฟล์ |
|---|---|---|
| กระดาน | 8 ช่องเรียงเส้นตรง `N_TILES = 8`, ทิศประจำช่องคงที่ `N N E E S S W W` | `main.gd` |
| การเดิน | โทเคนเดินช่อง 0 → 7 เรียงลำดับ แวะเฉพาะช่องที่มีการ์ด/คริสตัล/โทเท็ม (`walk_back` เดินย้อนได้) | `battle_manager.gd: build_walk_steps` |

**ปัญหา:** "รูปทรงของเส้นทาง" ไม่มีอยู่จริง เพราะเส้นทางเป็นเส้นตรงเสมอ ทิศของการ์ดจึงเป็นแค่ป้ายที่ใช้เทียบกับทิศช่อง ความต่างของบิลด์จึงมาจากตัวคูณใน Artifact ซึ่งคือ loop แบบ Balatro

## 3. Core loop ใหม่

### 3.1 กระดาน 2 มิติ
- กระดานกริด (เสนอ 5×5, ปรับได้) ช่องเริ่มต้นกำหนดต่อด่าน/ต่อศัตรู
- ผู้เล่นวางการ์ดลงช่อง การ์ดแต่ละใบมี **ทิศ** (N/E/S/W) และ **สี** เหมือนเดิม

### 3.2 กติกาการเดิน
1. โทเคนเริ่มที่ช่องเริ่มต้น
2. ถึงช่องที่มีการ์ด → ได้ผลของการ์ด แล้ว **เลี้ยวตามทิศของการ์ด**
3. ช่องว่าง → เดินตรงต่อในทิศเดิม
4. จบการเดินเมื่อ: ออกนอกกระดาน (**ชนขอบ**), ย้อนเข้าช่องที่เคยผ่านครั้งที่ 2 (**วนลูป**, ผ่านซ้ำได้สูงสุด 1 รอบ), หรือครบเพดานก้าว (เสนอ 24)
5. ช่องที่เคยผ่านแล้วถูกตัดผ่าน = **จุดตัด**

> ผู้เล่นออกแบบเส้นทางโดยเลือกว่าจะวางการ์ดทิศไหนที่ช่องไหน เส้นทางยาว/วน/ตัดกัน = ผลที่ต่างกัน

### 3.3 สิ่งที่วัดจากเส้นทาง (path metrics)
เหตุการณ์/ค่าที่ Artifact และ Chaos อ่านได้:

| ค่า | ความหมาย |
|---|---|
| `streak(dir)` | ก้าวติดต่อกันในทิศเดียวกัน (ต่อยอดจาก `tile_direction_run` เดิม) |
| `turns` | จำนวนครั้งที่เลี้ยว |
| `loops` | จำนวนครั้งที่วนกลับเข้าเส้นทางตัวเอง |
| `crossings` | จำนวนจุดตัด |
| `wall_hits` | ชนขอบ |
| `length` | จำนวนช่องที่ผ่าน |
| `cult_set` | ทิศที่ใช้ในเส้นทาง (ครบ 4 ทิศ = ครบวงลัทธิ) |

### 3.4 ดาเมจ
- ฐาน: ผลรวมค่าของการ์ดบนเส้นทาง (กลุ่ม Stone เดิมใช้ต่อ โดยนิยาม "ติดกัน" เป็นติดกันบนเส้นทาง ไม่ใช่ติดกันบนแถว)
- ตัวคูณหลักมาจาก **path metrics** (เช่น `mult += streak`, `mult += loops*2`) ไม่ใช่การสะสม Artifact
- เพดานความซ้อนของ `×mult` จาก Artifact: 1 ชิ้นต่อ run ที่คูณแบบทวีคูณได้ (ที่เหลือเป็นบวก) เพื่อไม่ให้กลับไปเป็นสูตร chips×mult แบบเดิม

## 4. การปรับ Artifact / Chaos / Stone

- **Artifact** (`data/artifacts/*.tres`): เพิ่ม hook ใหม่ใน `ArtifactSystem` เช่น `on_turn`, `on_loop`, `on_cross`, `on_wall`, `path_end` และ `StatEffect.source` ใหม่ (`streak`, `turns`, `loops`, `crossings`)
  - Artifact เดิมที่อิงทิศ (`north5`, `dirNHit`, `northStreak` ...) แปลงเป็น "ทิศนี้ทำงานเมื่อผ่านช่อง/เลี้ยวตามทิศนั้น"
  - Artifact ที่ +atk/×mult ล้วนๆ (`mult2`, `add5`, `atk15`) เก็บไว้เป็นของพื้นฐาน ลดบทบาท
  - เพิ่ม Artifact ชุด "ลัทธิ" 4 ตัว (หนึ่งต่อทิศ) เป็นแกนของบิลด์ เช่น ลัทธิเหนือ = สายตรงยาว, ลัทธิตะวันตก = วนลูป
- **Chaos** (`data/chaos/*.tres`): ปรับเป็นเครื่องมือแก้เส้นทาง เช่น เปลี่ยนทิศการ์ด (มีแล้ว), กำแพงกั้น, ประตูเทเลพอร์ต, ลูกศรบนช่องว่าง
- **Stone**: คงสูตรเดิม เปลี่ยนนิยามการวัดความติดกัน
- **โทเท็ม/คริสตัล**: คงไว้ เป็นช่องพิเศษบนกริด (`totem_attack` ที่อิงตำแหน่งช่องต้องคิดใหม่)

## 6. ลำดับการทำ (เฟส)

แต่ละเฟสจบด้วย `build.sh --check` ผ่าน และเล่นได้ ไม่ทำให้เกมพังค้าง

**เฟส 0: Prototype ตรรกะล้วน (ไม่มี UI)**
- เขียน `PathWalker` เป็นฟังก์ชันบริสุทธิ์: ใส่กริด+การ์ด → ได้เส้นทางและ path metrics
- เขียนชุดทดสอบ headless (`tools/parity/path_regress.gd`) เช่นเดียวกับ `artifact_regress.gd`
- เกณฑ์ผ่าน: เส้นทางตัวอย่าง 10 แบบให้ metrics ตามที่คำนวณมือ

**เฟส 1: กริดกับ UI ขั้นต่ำ**
- กระดาน 5×5 ใน scene เดิม วาง/ย้ายการ์ด ลูกศรทิศบนการ์ด โทเคนเดินตามเส้นทางแบบไม่มีเอฟเฟกต์พิเศษ
- ดาเมจ = ฐานจากการ์ดบนเส้นทาง × ตัวคูณเดียว เพื่อเล่นจบด่านได้

**เฟส 2: Artifact บนเส้นทาง**
- hook ใหม่ + `StatEffect` source ใหม่, แปลง Artifact เดิมที่อิงทิศ, เพิ่มชุดลัทธิ 4 ตัว
- ตัดสินใจเรื่องเพดาน ×mult

**เฟส 3: Chaos, โทเท็ม, คริสตัล, Stone**
- ปรับให้เข้ากับกริด, เพิ่มวัตถุกั้น/เทเลพอร์ต

**เฟส 4: Preview เส้นทาง + จูน**
- วาดเส้นทางที่จะเดินก่อนกดเดิน (สำคัญมากสำหรับเกมแนว "ออกแบบเส้นทาง"), จูนตัวเลขศัตรู/ด่าน/ร้านค้า, `--regress --update`

## 7. ความเสี่ยง

1. **เกมกลายเป็นปริศนา**: ถ้าเส้นทางมีคำตอบที่ดีที่สุดชัดเจน ความสนุกจะหาย ต้องมีสุ่มจากมือการ์ด + Chaos และคุมให้มีหลายทางที่ดีพอกัน
2. **อ่านเส้นทางยาก**: ต้องมี preview และสีเส้นทางชัด ไม่งั้นผู้เล่นเดาไม่ออก (เฟส 4 จึงห้ามข้าม)
3. **งาน UI ใหญ่**: `ui_renderer.gd`, `slot_drag.gd` ผูกกับแถวเดียวมาก
4. **ตัวเลขเดิมใช้ไม่ได้**: ศัตรู/รางวัล/ราคาร้านต้องจูนใหม่ ใช้ `--regress --update` เฉพาะหลังตั้งใจเปลี่ยน
5. **ความเข้ากันได้ของ save/สถานะ** (ถ้ามี): ยังไม่ได้ตรวจ

## 8. คำถามที่ต้องตัดสินใจก่อนเริ่มเฟส 0

1. ขนาดกริดและช่องเริ่ม: 5×5 ช่องเริ่มคงที่ หรือเปลี่ยนตามด่าน?
2. จำนวนการ์ดที่วางได้ต่อรอบ: เท่าเดิม (ตามจำนวนมือ) หรือจำกัดตามขนาดกริด?
3. การวนลูป: อนุญาตผ่านซ้ำกี่รอบ และให้ผลเป็นโบนัสหรือจบทันที?
4. ช่องว่าง: "เดินตรง" หรือ "หยุด"? (เดินตรงสร้างเส้นยาว หยุดทำให้ต้องวางการ์ดต่อเนื่อง)
5. เก็บ `walk_back` (เดินย้อน) ไว้ไหม หรือให้ลูป/ย้อนมาจากเส้นทางเอง?
6. ทิศประจำช่อง (`TILE_DIR`) เดิม: ยกเลิก หรือเปลี่ยนเป็น "ช่องมีทิศพิเศษ" เป็นวัตถุบนกริด?

# แผน Domino Run (สารบัญ + สถานะ)

อ่านไฟล์นี้ก่อนเสมอ แล้วไปที่เอกสารของเฟสที่กำลังทำ (`docs/domino/phase-N.md`). หลักการอยู่ใน `docs/design-principles.md`.
ข้อเสนอเดิมมาจาก advisor (2026-11-13). เอกสารแต่ละเฟสเขียนให้เริ่มงานใน session ใหม่ได้โดยไม่ต้องมีบริบทเดิม.

## แกนเกม
- แต่ละเทิร์นมี Gem 3 ใบ (แดง = โจมตี 4, น้ำเงิน = โล่ 3) ผู้เล่นวางเองลงช่อง 1×8 แล้วกดเดิน
- ลูกไฟวิ่งช่อง 1→8, Gem ป๊อปทันทีที่ผ่าน (เสียงสูงขึ้น จังหวะเร็วขึ้น), แดงยิงเลเซอร์ใส่ศัตรู
- ศัตรูมีธงโจมตีบนช่องหนึ่ง ตีตอนลูกไฟถึงช่องนั้น โล่นับเฉพาะที่ป๊อปก่อนถึง (รวมช่องธง)
- HP จริงทั้งสองฝั่ง ต่อเนื่องข้ามศัตรู
- การตัดสินใจฐานมีข้อเดียว (Gem ไหนก่อน/หลังธง) ส่วนที่ต้องคิดจริงคือ Artifact ซึ่งเปลี่ยน "กฎของการวิ่ง" ไม่ใช่แค่ +ตัวเลข

## ของที่มีอยู่ตอนนี้ (v0.1.29)
- Domino เป็นฉากหลัก (`scenes/domino.tscn`); เกมเก่าและเครื่องมือเทียบ draft ถูกลบแล้ว (เฟส 6)
- `scenes/domino.tscn` → `scripts/domino/domino_view.gd` (วาดอย่างเดียว เล่นซ้ำ event) + `scripts/domino/domino_sim.gd` (กฎล้วน ไม่มี UI/await) + `domino_rule/artifact/catalog.gd` (ไม่มี `class_name` ใช้ `preload`)
- Artifact เป็นข้อมูล `data/domino/artifacts/*.tres` 12 ใบ; ผู้เล่นเริ่มด้วยช่องว่าง 5 ช่อง (แตะช่องเพื่อดูคำอธิบาย แตะสองช่องเพื่อสลับลำดับ) ได้ใบใหม่จากหน้ารางวัลหลังชนะ (`domino_reward.gd`); 10 ด่านแล้วหน้าจบ; ทดสอบเร็วด้วย `?arts=mirror,coal`
- เฟส 5: เหรียญ (ชนะ = 3 + ด่าน/2), บอสด่าน 3/6/9 (`data/domino/bosses/*.tres`: twin_flag drifter obsidian smoke bulwark) แล้วเข้าร้าน (`domino_shop.gd`: 4 ใบ ราคา 4/6/8 ตามความหายาก, สุ่มใหม่ 2+1 ต่อครั้ง, ขายครึ่งราคา); ด่านปกติยังเลือก 1 จาก 3; Artifact เศรษฐกิจ piggy, bounty. ตีความ drifter: ธงเลื่อนไปข้างหน้า 2 ช่องหลังตี รอบละครั้ง (อาจโดนตีซ้ำ) และผลักไม่ได้; push/move_flag ขยับเฉพาะธงแรก
- กริยาที่ sim รองรับ: damage shield heal repop bounce reflect_strike keep_gems spawn_gem move_flag set_route convert add_stat gold (kill trigger ผ่านได้แม้การวิ่งหยุดแล้ว); `convert` เป็น modifier ทำงานก่อนผลในตัวของ pop
- regress: `tools/parity/domino_regress.gd` (รันใน `build.sh --regress`); smoke `build.sh --check` พิมพ์ `TB_DOMINO_OK`
- `main.gd::_launch_arg("mode")` สลับฉาก
- ตัวละคร: `HERO_HOME`, `ENEMY_HOME`, `_react()` (tween ไป/กลับจากตำแหน่งบ้านเสมอ), `_laser()`, `_badge()`
- จูนค่า: `RED_DMG=4`, `BLUE_BLOCK=3`, HP ผู้เล่น 30, ศัตรู 18 ×1.25/ด่าน, ตีแรง 8 ×1.15/ด่าน, ชนะแล้วเติม HP 40%

## การตัดสินใจที่ตกลงแล้ว (อย่าถามซ้ำ)
- Gem น้ำเงินให้โล่ที่ตัว Gem (แก้ `design-principles.md` ข้อ 3 แล้ว)
- ผู้เล่นวางการ์ดเอง ไม่ใช่อัตโนมัติ
- ความยาวการวิ่งตอนเปิดกำแพงกระจกราว 3 วินาที เกินเพดาน 2.5 วินาที: จูนทีหลังด้วย `step_dur = min(0.20, 2.2/steps)` (เฟส 3)
- สัดส่วนสีสำรับ 60/15/15/10 ของเกมเดิม **ไม่ใช้**ใน Domino (มีแค่แดง/น้ำเงิน)
- ห้าม push ไป branch อื่นนอกจาก `ccr-676e0d29-r44gz1` โดยไม่ขออนุญาต; ทุก push ที่แตะไม่ใช่ `.md` ต้องเพิ่ม patch ของ `application/config/version`

## กติกาเก็บงานให้เสถียร
- ทุกหน้าจอที่เล่นได้ต้องมี version stamp มุมขวาล่าง (ผู้ใช้สั่ง 2026-11-13): view ใหม่ต้องเรียก `_add_version_stamp()`
- เล่นผ่านก่อนลบ: ห้ามลบของเก่าจนกว่าเฟส 6 และผู้ใช้ยืนยัน
- ปรึกษา `advisor` ก่อนตัดสินใจโครงสร้างข้อมูล และก่อนประกาศจบเฟสใหญ่ (เฟส 3 และ 6)
- ตัวเลข/สมดุลจูนใน `.tres` และค่าคงที่ ไม่แก้กริยา (verb)
- ดู `reference/pitfalls.md` ใน skill `tobeyond-dev` ก่อนเขียน UI/tween (บทเรียน: tween ต้องเริ่ม/จบที่ตำแหน่งบ้านเสมอ; class_name ใหม่ต้อง build ใหม่หรือใช้ `preload`)

## เริ่ม session ใหม่ทำอย่างไร
1. โหลด skill `tobeyond-dev`, อ่านไฟล์นี้, `docs/design-principles.md`, แล้ว `docs/domino/phase-N.md` ของเฟสถัดไป

3. ทำตามลำดับงานในเอกสารเฟส ใช้ `advisor` ตามจุดที่ระบุ
4. จบเฟส: อัปเดตตารางสถานะด้านบน, เพิ่ม patch version, commit/push, แจ้งลิงก์ preview

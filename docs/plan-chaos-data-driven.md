# Plan: make Chaos data-driven (like Artifacts)

Goal: a new Chaos card of an existing behaviour = one `.tres`; a new behaviour = one small `*_chaos_effect.gd`
(10-60 lines) + `.tres`. No edits to `chaos_controller.gd`, `board_calc.gd`, `ui_renderer.gd`, `shop_manager.gd`.
Constraint: no behaviour change (same numbers, Thai text, rounding), checked with `artifact_regress` + `build.sh --check`.

## Where `kind` is switched on today
- `chaos_controller.gd`: `on_slot_pressed` (hand-use vs tile-target kinds), `apply_hand` (color/dirc/goldify/destroy), `apply_to_tile` (tdir/mtile/xmult/xatk/crystal), `finish`.
- `board_calc.gd` 90, 116-120 and `ui_renderer.gd` 261-265, 297-303: three state dicts `chaos_mult_tiles` (MULT +5), `chaos_xmult_tiles` (MULT x1.2), `chaos_xatk_tiles` (ATK x1.2), read for damage maths, badges and tile hints. Also `chaos_crystals` (HP) in battle_manager, ui_renderer, artifact_context.
- `shop_manager.gd`: `chaos_label/name/desc` (match on kind, Thai text), `_chaos_card_look` (bg/cover per kind), `_add_chaos_card` cover_text, `get_chaos_title/icon/sell_price` (linear search of the catalog by kind+col+dir).
- `ui_renderer.gd` 654-655: slot colour per kind. `reward_flow.gd`: boss drops `{"kind": "crystal"}`. `debug_scenarios.gd` and `artifact_regress.gd` build `{"kind": ...}` dicts and write the three dicts directly.

## Design
1. `ChaosData` gets `id` (file name stem), and Thai text fields `label`, `desc` (templates with `%col`/`%dir` filled by the loader), `card_bg`, `text_color`, `cover` key, `cover_text`. Owned card dict keeps `kind/col/dir` (compat) and adds `id`; lookups by `id` replace the catalog scans.
2. New `ChaosEffect` resource (base, `scripts/artifacts/chaos/chaos_effect.gd`), with `needs_tile: bool` and:
   - `use_hand(ctx, card, picked) -> String` (returns "" on success, else the error toast; sets nothing on failure), result toast via `done_message`.
   - `use_tile(ctx, tile_idx) -> String` same convention.
   Subclasses: `ColorChaos(col)`, `DirChaos(dir)`, `TileDirChaos(dir)`, `TileMarkChaos(mark_id)`, `GoldifyChaos`, `DestroyChaos`, `CrystalChaos`. They write the same `main` state as now.
3. `ChaosController` becomes generic: look up `ChaosData` by `card.id`; `needs_tile` -> select slot, else `use_hand`; common `finish`. Remove all `kind` branches.
4. Tile marks: replace the three dicts with `chaos_marks: Dictionary` (mark_id -> {tile: true}) and a `ChaosMark` resource (mult_add, mult_mul, atk_mul, badge text/colour, hint text). `board_calc`/`ui_renderer` loop over marks instead of three hard-coded ifs. Rounding order of the existing three must be kept (MULT +5 first, then x1.2 MULT, then x1.2 ATK).
5. `shop_manager` reads label/name/desc/look from `ChaosData`; `get_chaos_*` become `ChaosCatalog.by_id(id)`.

## Phases (one commit each, checks after each)
A. `id` + generic lookups in shop_manager/ui (no new classes). B. `ChaosEffect` classes + generic controller. C. Marks generalisation (`chaos_marks`). D. Text/look fields moved from `match` blocks into `.tres`.

## Risks / questions
- Phase C touches damage maths (board_calc) and the regress/debug scripts that write the three dicts; regress must stay byte-identical.
- Is C worth it vs leaving the three dicts (new mark = edit 3 files)?
- Any save/serialisation of chaos cards (dict shape)? (none found so far)
- Does `.tres` with sub-resource effects of new script classes need `--import` to register class_names (yes, as with artifacts).

## Advisor review (adopted)
- Phase C (generalised marks) **deferred**: damage order (+5, x1.2 MULT, x1.2 ATK before `artifact_sys.land`), `passive_chaos_tile_count` semantics and chip order are fragile. `TileMarkChaos` exports `state_var` (e.g. `chaos_xmult_tiles`) and uses `main.get(state_var)` instead.
- Order: A (id + `make_card()` + `chaos_def(card)` with kind/col/dir fallback; route buy_chaos, give_random_chaos, reward_flow, debug_scenarios through it; drop dead `get_chaos_title/icon`) -> D (text/look fields in `.tres`, generated by a one-shot script so text is byte-identical; `card_bg` and `slot_bg` are different) -> B (ChaosEffect classes, generic controller; blank check stays in controller except destroy).
- Keep `kind` on cards (regress prints it) and `catalog_order` unchanged (drives shop RNG). No `%col` templating: store literal Thai strings.
